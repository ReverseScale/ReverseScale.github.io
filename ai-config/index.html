Why it exists

AI tooling should feel like infrastructure, not folklore.

Personal setup drifts across machines; long sessions accumulate conflicting instructions; multi-agent work hides ownership in chat. AI Config versions the durable parts and exposes the collaboration state that must remain reviewable.

DECISION RULE

Bind work by capability and authority—not by provider name. Keep ambiguous work with the supervisor; dispatch only bounded tasks.

A real configuration surface

More than dotfiles. An operating model.

The repository makes each layer inspectable: what loads, which tools exist, where context comes from, and what proof closes a task.

Built-in guardrails

Autonomy with an edge.

Coordination is useful only when its authority, state, and completion boundary stay visible.

01 / SOURCE

Versioned configuration

Hooks, Skills, MCP definitions, and machine setup share one reviewable source of truth.

02 / AUTHORITY

Explicit permissions

Each agent receives a named role and the smallest workspace access its task requires.

03 / ISOLATION

Protected workspaces

Branches, worktrees, devices, and leases keep concurrent tasks from contaminating one another.

04 / EVIDENCE

Auditable outcomes

Diffs, tests, previews, task state, and handoffs make completion inspectable beyond a chat transcript.

System boundary

Local-first by design.

A Supervisor owns Room state. Adapters resume compatible coding sessions. Policy defines who can act, what they can touch, and which evidence must exist before a result returns to the human.
