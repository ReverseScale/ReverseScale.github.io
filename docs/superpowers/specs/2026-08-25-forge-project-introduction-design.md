# Forge 项目介绍页精修设计

## 目标

将 Forge 从首页项目卡扩展为可独立阅读和验收的项目案例页，回答四个问题：它解决什么学习问题、用户实际能使用哪些产品能力、四个 Agent 如何形成闭环、Web/MCP 与持久化能力如何组成完整系统。

## 设计取舍

- 首屏使用真实的导师会话示例呈现产品价值，避免仅用抽象口号或技术栈列表介绍项目。
- 学习闭环采用可交互的四阶段检查器。每个阶段显式展示 input、decision、tool 和 output，使 Agent 分工及交接契约可验证。
- 产品能力区按真实使用路径解释九项能力：加权学习方向、项目上下文、Deep/Quick 训练、提示与教师反馈、能力画像与间隔复习、题库治理、Web/MCP 双入口、运行时模型设置，以及按 Agent 调用归因的 token 统计。
- token 能力显式拆分成本证据与运行证据：前者记录输入/输出 token，后者记录耗时、状态与错误。当前实现边界是 Orchestrator 链路已写入 `agent_runs.token_cost`；Web/MCP 的用量看板与阈值告警仍属于后续规划。
- 一次训练旅程从方向设置一直追踪到评分、优点、改进项和下一步，并将“当前可用”与“后续规划”并列呈现。沙箱代码评测、能力雷达、Git 活动题源和多人协作明确标记为规划，避免将路线图误写成已交付能力。
- Boundary 区的 MVP 状态条归属于右侧卡片组，并以 12px 行间距紧跟两张边界卡片；它不参与外层双列网格的第二行排布，避免横向列间距被误用为巨大的纵向留白。
- 交互数据放在 `src/forge-model.mjs`，DOM 行为放在 `src/forge.js`，页面静态内容在 JavaScript 不可用时仍然完整可读。
- 视觉使用排版、CSS 图形和信息层级表达，不引入与项目无关的图片或一次性视觉资产。

## 交互与无障碍

- 四阶段支持点击、左右方向键、Home、End 和自动播放。
- 激活状态同步更新 `aria-selected`、焦点顺序和 `aria-live` 检查器内容。
- `prefers-reduced-motion` 下关闭连续播放，仅执行单步切换。
- 720px 以下重排会话工作台、能力卡片、训练旅程、阶段列表、架构图和边界卡片，保留触控可用面积。

## 验证边界

- `tests/test_forge_project.py` 校验首页集成、九项产品能力、token 统计与运行监控边界、交付范围边界、学习闭环顺序、独立游标状态和无障碍交互契约。
- 本地预览需同时确认 `/forge/`、`/src/forge.js`、`/src/forge-model.mjs` 和 `/src/forge.css` 返回成功。
