# App 架构动画解说页设计

## 目标

在个人作品站中新增一个独立的 App 架构知识模块，通过精致交互与关系动画说明常规 App 从单体代码演进到通用组件、业务模块、App 组装和规模化治理的过程。该模块不是项目介绍，不进入现有 `projectLinks`，也不暗示它是可安装产品。页面内容首版统一使用简体中文，代码术语和 API 名称保留原文。

## 信息架构

首页在项目区之后增加独立的 `Architecture explainer` 区域，并链接到 `/app-architecture/`。首页入口沿用作品站的英文语言环境，包括导航、说明、预览节点和无障碍文案；解说详情页继续使用简体中文，避免入口破坏首页一致性，也不改变既定的中文叙事。解说页包含：

1. 页面定位：说明它是一份交互式架构解说。
2. 八关重构玩法：`抽出通用能力`、`建立业务边界`、`收拢数据所有权`、`控制依赖方向`、`设计模块契约`、`组装 App`、`治理运行时变化`、`设计失败降级`。
3. 架构重构游戏：职责卡片、目标边界和正确归属由关卡数据声明并渲染。
4. 即时反馈：同步展示判断原则、错误原因、关卡进度和模拟架构状态。
5. 运行时横切能力：说明模块、资源、配置实验与 Telemetry 的职责。
6. CI/CD 交付流水线：说明代码如何经过构建、门禁、签名、灰度和观测进入设备。
7. 设计原则：给出依赖方向、业务边界和共享能力的判断标准。

## 独立视角

页面把 App Architecture 和 Delivery Pipeline 设计为两个独立区块：

- **App Architecture Refactor Game**回答“App 内部如何从职责混杂演进到清晰的组件、业务模块、壳、Router 和平台 Runtime”。用户通过架构决策亲手完成重构。
- **Delivery Pipeline**回答“一次变更怎样按时间顺序成为运行在设备上的 App，并怎样把结果反馈回来”。节点从左到右覆盖代码变更、变更预检、多技术栈构建、质量与包大小 Gate、签名与制品库、渐进式发布、App Runtime 和 Telemetry 反馈。

两个区块共享领域术语，但不共享布局、展开状态或交互控制器。`App Runtime` 是 Pipeline 中的普通完整节点，不再承担打开 App Architecture 的入口。这样 App 玩法可以独立增加关卡和边界，Pipeline 也可以独立扩充交付节点与详情。

Pipeline 的八个节点都是可交互的完整信息单元。节点卡片只承担扫描与导航，选中后由统一详情面板解释该阶段的输入、关键动作、输出、确定性门禁、失败策略和可观测信号，避免为了“补全内容”把所有文字同时堆在时间线上。

## 架构重构游戏

游戏使用统一的 `piece → target zone` 数据契约。每张职责卡片声明正确目标和解释原因，每关只声明任务、判断原则、目标边界和卡片，不为特定关卡编写判定分支。

当前版本包含八关：

- 抽出通用能力：区分业务规则、UI 组件和功能组件。
- 建立业务边界：把业务 UI 与规则归入首页、目录和结算模块。
- 收拢数据所有权：让首页、目录、结算和平台状态拥有唯一业务 Owner。
- 控制依赖方向：区分 Feature → Domain、Domain Contract、Platform Adapter 和需要拆除的反向依赖。
- 设计模块契约：区分 Public API、Route Contract、Domain Event 与模块内部实现。
- 组装 App：让 App 壳负责注册、Router 负责跨模块协议，模块不直接依赖彼此。
- 治理运行时变化：分别治理动态交付、资源、配置实验和 Telemetry。
- 设计失败降级：用 Built-in Baseline、Last Known Good、Kill Switch 和 Recovery Signals 形成恢复闭环。

拖拽不是唯一入口。键盘或触屏用户可以先选择卡片，再点击目标边界；两种操作共用同一判定函数。错误归类不扣除进度，而是解释职责为什么属于另一个边界。正确归类会进入目标区并更新明确标为“模拟”的耦合度、边界清晰度和发布隔离度。

## 交互与动画

- Pipeline 进入视口时，横向轨道、节点和图标按顺序显现，流光从代码变更移动到 App Runtime，再进入 Telemetry 反馈。
- 用户可选择任一 Pipeline 节点查看完整详情；键盘左右方向键沿交付顺序移动，详情面板使用短促的淡入位移动画反馈上下文切换。
- 详情不是六个并列指标卡，而是统一“节点工作台”：上层以 `输入 → 关键动作 → 输出` 表达处理主链，下层用 Gate、失败策略和可观测信号构成安全底座；AI 约束作为一条轻量说明嵌入底部。
- App Architecture 使用八关任务导航；完成当前关卡才解锁下一关，已完成关卡可以回看。
- 每关首次进入时随机打乱待整理职责，重置本关时再次洗牌；洗牌只改变显示顺序，不改变职责的语义归属和通用判定契约。
- 待整理职责保留轻微错位；右侧不是固定网格卡片，而是由关卡数据声明的架构拓扑画布：组件关展示业务层对两类通用能力的依赖，模块关展示并列业务边界，组装关展示 App 壳、Router、业务模块与通用组件的层次，Runtime 关展示四类横切平台能力。职责归位后进入对应拓扑节点，以玩家行为直接表达“从混乱到有序”。
- 首屏使用明确的“开始架构挑战”按钮直接进入第一张职责卡；游戏 HUD 同步显示行动数、连续正确次数和秩序值，错误归类使用短促震动与语义解释，正确归类使用归位动画，完成关卡后提供庆祝反馈和下一关入口。
- 玩家可以重置当前关卡或在最终关重新挑战。互动结果通过 `data-game-*` DOM 状态和 `architecture-game:event` 自定义事件暴露，方便无第三方分析服务时进行浏览器验证，未来也可由站内统计适配器订阅。
- 游戏反馈、关卡状态和 Pipeline 详情分别使用独立的 `aria-live` / `tabpanel` 语义，不互相修改状态。
- Pipeline 和横轴节点使用同一套自包含 SVG 图标语言：统一圆角、`1.7px` 描边和语义色，不加载外部图标字体或网络资源。图标微动只表达构建、校验、交付和观测等真实状态。
- 组件化与模块化必须使用不同的视觉语法：组件是不拥有业务逻辑的通用能力，至少区分 `UI 组件库` 和 `功能组件库`；模块由 `业务 UI / 业务逻辑 / 组件依赖` 组成，是完整的业务变化单元。
- 最终组装阶段必须明确展示 `App 壳` 注册各业务模块，各模块通过 `Router` 通信，并共同依赖通用组件。`Router` 只承载路由协议，不拥有业务逻辑。
- 大型 App 阶段在既有模块边界之上展示四类运行时职责：
  - 模块与路由：Native、Flutter、React Native 等技术栈以独立产物和 `Module Manifest` 接入，由清单生成动态路由表。
  - 动态交付 Runtime：统一管理模块和资源包的版本检查、下载、验签、原子激活、失败熔断与回滚。
  - 资源与配置：i18n、图片和主题首先是随 App 或模块构建的内置资源；可选热修复只下发版本化资源包。动态配置、Feature Flag 与 A/B Test 独立负责运行时参数和实验分流，不与 i18n 混为一个决策中心。
  - 数据与可观测：Telemetry Runtime 收集 Log、埋点与指标，形成从设备现场到发布决策的数据反馈。
- CI/CD 使用横向时间线表达：`代码变更 → 变更预检 → 多技术栈构建 → 质量与包大小 Gate → 签名与制品库 → 渐进式发布 → App Runtime → Telemetry 反馈`。
- 包大小是正式 Gate，而不是构建日志中的一个数字。门禁同时检查总量预算、模块增量、热更增量、趋势和依赖/资源归因；例外必须有责任人、原因和有效期。
- AI 作为贯穿流水线的辅助轨道：用于影响分析、测试建议、体积归因、失败诊断、发布风险和异常关联。AI 输出证据与建议，确定性规则、策略和人工授权仍是发布与回滚的最终门禁。
- 图中节点可以获得焦点，便于键盘用户查看职责说明。
- `prefers-reduced-motion: reduce` 下移除卡片位移和 Pipeline 流光，保留完整静态信息与所有操作能力。
- 移动端保留横向可滑动的 Pipeline，并提供首尾渐隐和当前节点自动对齐；游戏关卡导航也可横向滚动，待整理区和目标边界改为单列，点击归类作为触屏稳定路径。
- 标题层级保持克制：桌面主标题上限为 `52px`，主区块标题上限为 `34px`，任务标题上限为 `23px`；移动端主标题上限为 `34px`、主区块标题上限为 `27px`，避免标题与游戏内容争夺注意力。
- 八关复用同一套卡片、目标区、判定、反馈和解锁机制；新增关卡只扩展数据，不为特定职责硬编码交互分支。

## 技术边界

- 继续使用仓库现有的无构建静态站结构。
- 页面入口为 `app-architecture/index.html`。
- 动画逻辑集中在 `src/app-architecture.js`，样式集中在 `src/app-architecture.css`。
- 游戏关卡、职责卡片、目标边界、正确归属和解释原因来自同一份只读数据；通用控制器负责选择、拖拽、判定、反馈和解锁。
- 首页只增加知识模块入口和共享导航链接，不修改三个项目的既有数据契约。

## 可观测性与验证

首版不接入外部分析服务，避免在未确定隐私和统计平台前引入第三方请求。交互状态通过 DOM 属性和 `aria-live` 呈现，可由浏览器测试直接观察。自动化测试覆盖中文内容、页面入口、八关数据契约、正确与错误归类、游戏与 Pipeline 分离、包大小门禁、AI 辅助边界、手动控制和无障碍降级；交付前检查桌面与移动视口。
