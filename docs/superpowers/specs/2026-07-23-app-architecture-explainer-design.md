# App 架构动画解说页设计

## 目标

在个人作品站中新增一个独立的 App 架构知识模块，通过精致交互与关系动画说明常规 App 从单体代码演进到通用组件、业务模块、App 组装和规模化治理的过程。该模块不是项目介绍，不进入现有 `projectLinks`，也不暗示它是可安装产品。页面内容首版统一使用简体中文，代码术语和 API 名称保留原文。

## 信息架构

首页在项目区之后增加独立的 `Architecture explainer` 区域，并链接到 `/app-architecture/`。首页入口沿用作品站的英文语言环境，包括导航、说明、预览节点和无障碍文案；解说详情页继续使用简体中文，避免入口破坏首页一致性，也不改变既定的中文叙事。解说页包含：

1. 页面定位：说明它是一份交互式架构解说。
2. 五阶段叙事：`单体应用`、`通用组件`、`业务模块`、`App 组装`、`大型 App`。
3. 动态架构图：节点和依赖关系由阶段数据声明并渲染。
4. 阶段说明：同步展示当前变化、收益与仍需注意的边界。
5. 运行时横切能力：说明模块、资源、配置实验与 Telemetry 的职责。
6. CI/CD 交付流水线：说明代码如何经过构建、门禁、签名、灰度和观测进入设备。
7. 设计原则：给出依赖方向、业务边界和共享能力的判断标准。

## 二维主图

页面使用同一张二维系统图连接两个正交维度：

- **横轴 `X · Delivery Pipeline`**回答“一次变更怎样按时间顺序成为运行在设备上的 App，并怎样把结果反馈回来”。节点从左到右覆盖代码变更、变更预检、多技术栈构建、质量与包大小 Gate、签名与制品库、渐进式发布、App Runtime 和 Telemetry 反馈。
- **纵轴 `Y · App Architecture`**从横轴的 `App Runtime` 节点向下展开，回答“App 内部如何从单体演进到组件、业务模块、壳与 Router，再到大型 App 的动态运行时”。

App 不是与 Pipeline 并列的另一块内容，而是 Pipeline 上的一个可展开节点。横轴保留生命周期和时间方向，纵轴保留 App 内部结构的深挖语义；两者在 `App Runtime` 交点连接，不互相侵占职责。

Pipeline 的八个节点都是可交互的完整信息单元。节点卡片只承担扫描与导航，选中后由统一详情面板解释该阶段的输入、关键动作、输出、确定性门禁、失败策略和可观测信号，避免为了“补全内容”把所有文字同时堆在时间线上。

## 可扩展轴协议

Pipeline 节点通过数据声明可选的 `axisId`，向下展开的专题内容由独立面板注册表按 `axisId` 渲染。交互控制器只处理“当前展开哪个轴”，不识别 App、Gate 或 Telemetry 的业务名称。

首版只注册 `app-architecture` 纵轴。后续可以在不修改 Pipeline 布局和通用交互的前提下继续增加：

- `build-matrix`：从多技术栈构建节点展开 Native、Flutter、React Native 的构建与测试矩阵。
- `quality-gates`：从质量门禁节点展开测试、包大小、性能、安全和供应链门禁。
- `telemetry-loop`：从 Telemetry 节点展开 Log、埋点、指标、实验和发布决策链路。

## 交互与动画

- 二维主图进入视口时，横向轨道、节点和图标按顺序显现，流光沿 Pipeline 从代码变更移动到 App，再进入 Telemetry 反馈。
- 用户可选择任一 Pipeline 节点查看完整详情；键盘左右方向键沿交付顺序移动，详情面板使用短促的淡入位移动画反馈上下文切换。
- 详情不是六个并列指标卡，而是统一“节点工作台”：上层以 `输入 → 关键动作 → 输出` 表达处理主链，下层用 Gate、失败策略和可观测信号构成安全底座；AI 约束作为一条轻量说明嵌入底部。
- `App Runtime` 默认展开纵轴，用户可以收起或再次展开；纵轴从该节点向下绘制连接线并渐显，明确它属于这个 Pipeline 节点。
- App Architecture 是 `App Runtime` 工作台的连续深挖区，不再以另一张悬浮大卡片出现。用户通过顶部五阶段步骤导航选择演进阶段；节点在同一画布内移动、缩放、重组，而不是整张图瞬间替换。
- 依赖线重新绘制时显示沿路径运动的数据粒子，用动态关系而不是纯装饰体现依赖方向。
- Pipeline 和横轴节点使用同一套自包含 SVG 图标语言：统一圆角、`1.7px` 描边和语义色，不加载外部图标字体或网络资源。图标微动只表达构建、校验、交付和观测等真实状态。
- 组件化与模块化必须使用不同的视觉语法：组件是不拥有业务逻辑的通用能力，至少区分 `UI 组件库` 和 `功能组件库`；模块由 `业务 UI / 业务逻辑 / 组件依赖` 组成，是完整的业务变化单元。
- 最终组装阶段必须明确展示 `App 壳` 注册各业务模块，各模块通过 `Router` 通信，并共同依赖通用组件。`Router` 只承载路由协议，不拥有业务逻辑。
- 大型 App 阶段在既有模块边界之上展示四类运行时职责：
  - 模块与路由：Native、Flutter、React Native 等技术栈以独立产物和 `Module Manifest` 接入，由清单生成动态路由表。
  - 动态交付 Runtime：统一管理模块和资源包的版本检查、下载、验签、原子激活、失败熔断与回滚。
  - 资源与配置：i18n、图片和主题首先是随 App 或模块构建的内置资源；可选热修复只下发版本化资源包。动态配置、Feature Flag 与 A/B Test 独立负责运行时参数和实验分流，不与 i18n 混为一个决策中心。
  - 数据与可观测：Telemetry Runtime 收集 Log、埋点与指标，形成从设备现场到发布决策的数据反馈。
- CI/CD 使用横向时间线表达：`代码变更 → 变更预检 → 多技术栈构建 → 质量与包大小 Gate → 签名与制品库 → 渐进式发布 → App Runtime → Telemetry 反馈`。
- 包大小是正式 Gate，而不是构建日志中的一个数字。门禁同时检查总量预算、模块增量、热更增量、趋势和依赖/资源归因；例外必须有责任人、原因和有效期。
- AI 作为贯穿流水线的辅助轨道：用于影响分析、测试建议、体积归因、失败诊断、发布风险和异常关联。AI 输出证据与建议，确定性规则、策略和人工授权仍是发布与回滚的最终门禁。
- 图中节点可以获得焦点，便于键盘用户查看职责说明。
- `prefers-reduced-motion: reduce` 下移除节点位移和粒子运动，保留完整静态信息。
- 移动端保留横向可滑动的 Pipeline，并提供首尾渐隐和当前节点自动对齐；节点详情与 App 纵轴改为块级内容，App 阶段导航也可横向滚动，避免把桌面二维关系压成难读的小字。
- 标题层级保持克制：桌面主标题上限为 `52px`，主区块标题上限为 `34px`，App 轴标题上限为 `24px`，阶段说明标题上限为 `22px`；移动端主标题上限为 `34px`、主区块标题上限为 `27px`，避免标题与架构图争夺注意力。
- 第五阶段仍复用固定节点槽位与关系粒子；模块注册、路由通信、资源依赖、产物交付和数据采集必须使用可区分的关系颜色。各阶段节点数量不足时使用隐藏占位，不为第五阶段单独硬编码 DOM。

## 技术边界

- 继续使用仓库现有的无构建静态站结构。
- 页面入口为 `app-architecture/index.html`。
- 动画逻辑集中在 `src/app-architecture.js`，样式集中在 `src/app-architecture.css`。
- 阶段内容、节点和依赖边全部来自同一份只读数据；节点槽位跨阶段复用，通过位置数据驱动重排，避免为单个画面硬编码 DOM。
- 首页只增加知识模块入口和共享导航链接，不修改三个项目的既有数据契约。

## 可观测性与验证

首版不接入外部分析服务，避免在未确定隐私和统计平台前引入第三方请求。交互状态通过 DOM 属性和 `aria-live` 呈现，可由浏览器测试直接观察。自动化测试覆盖中文内容、页面入口、五阶段数据契约、运行时与交付视角分离、包大小门禁、AI 辅助边界、入场动画、粒子流动、手动控制和无障碍降级；交付前检查桌面与移动视口。
