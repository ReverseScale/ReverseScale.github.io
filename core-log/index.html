Cross-runtime lifecycle safety

Destroy one logger
without disturbing another.

Logger identity survives language boundaries without turning a native address into a promise. Each call, callback, and engine cleanup is tied to an exact active instance generation.

01 / IDENTITY Opaque handles Old IDs cannot resolve to a recreated logger, even if memory addresses are reused.
02 / CONCURRENCY Leased calls Destroy retires the instance first and delays deletion until active calls finish.
03 / OWNERSHIP Generation tokens A detached Flutter engine cannot clear a newer engine's rotation callback.
failure contract Retired handles fail closed. They never drift into a new logger generation or report false success across JNI, Objective-C++, and Dart FFI.
